# 依维希开发版设计

依据用户要求直接开发，采用现有《设计方案 v0.5》《卡牌 v0.4》，不重新设计玩法。原始材料保留在 `/home/ika/temp/slay_mod`。初始遗物“月眼之镰”由用户确认，用于承载机制，不增加策划外数值奖励。

## 技术选择

使用 C# / .NET 9、游戏 v0.107.1 与 BaseLib 3.4.7 的实际本地程序集。直接继承 BaseLib 角色/卡牌/状态接口；尚未完成的角色美术引用游戏资源作为占位。编译和打包不自动修改游戏目录。

项目分成独立可测试的 `Ivich.Core` 和真正游戏适配 `Ivich.Mod`。核心负责资源互斥、精确生命比例、伤害公式、冻结/终焉、成长和延迟队列等确定性规则；适配层负责游戏命令、事件、选择、UI、存档与模型注册。全卡池数据保留原文与编号，后续可复核和生成美术导入清单。

直接把所有机制写入游戏钩子会使边界难以验证；纯模拟器不能交付游戏角色。因此选规则层与真实适配并行开发，并分别报告测试与游戏验证状态。

## 首个开发版边界

完成角色入口、11 张初始牌组、机制遗物、基础及普通卡的实际效果；实现独立资源、核心状态、成长进阶与可替换资源路径。全 82 张卡建立可追溯的内容目录，未接入的卡不进入游戏奖励池。每个已启用内容都必须有对应实际执行路径。

复杂能力、封存/吟唱及先古入口依照实现进度在内容状态表明确区分；不制造未验证的欧罗巴斯入口，不宣称已通过游戏实测。规则层可先覆盖其确定性行为，不能将此等同游戏接入完成。

## 验证

对资源隔离、生命代价、换形无刷血、冻结阈值、终焉基准、延迟快照和清场边界做自动化测试。使用真实游戏 DLL 编译适配层，核查模型目录和奖励池。发布 DLL/清单及安装说明，标明美术占位和需要游戏内确认的行为。
